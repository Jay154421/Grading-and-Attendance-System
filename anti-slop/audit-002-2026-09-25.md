## Findings

1. [HIGH] R-32 (Hard Gate) No skip link and no focusable main landmark, so
   every keyboard visit re-tabs through the whole sidebar. HEAD contained zero
   `Skip to main` matches.
   Where: teacher-layout.jsx, student-layout.jsx.
   Status: FIXED. Harness: first Tab reaches `Skip to main content`, link is
   visible when focused, `main#main-content[tabindex="-1"]`.

2. [HIGH] R-32 (Hard Gate) Dialogs were plain `div`s: no `role="dialog"`, no
   `aria-modal`, no `aria-labelledby`, no focus trap, no focus move on open, no
   focus restore on close, no scroll lock. HEAD contained zero `aria-modal`.
   Where: SubjectsPage (add/edit/delete), StudentsPage (add/edit).
   Status: FIXED via `ui/Modal.jsx`. Harness: opens from Add Subject, labelled
   by its visible title, focus lands on Close, stays inside after 18 Tabs,
   Escape closes, focus returns to "Add Subject".

3. [HIGH] R-32 (Hard Gate) Login Sign in/Register were plain `onClick`
   buttons: no `role="tablist"/"tab"`, no `aria-selected`, no `aria-controls`,
   no `tabpanel`, no arrow-key navigation. HEAD contained zero `role="tablist"`.
   Where: login-form.jsx.
   Status: FIXED. Harness: ArrowRight selects + focuses `tab-register`,
   ArrowLeft moves back, each panel is labelled by its tab, one visible `h1`.

4. [HIGH] R-32 (Hard Gate) Focus indication was partly decorative: inputs
   declared `focus:ring-red-500` without a ring width, so the ring never
   rendered (HEAD: `focus:ring-red-500` present, `ring-2` absent in
   AttendanceRecord.jsx and StudentGradesPage.jsx); header/drawer/sidebar
   controls had no `focus-visible` ring at all.
   Where: all form fields, hamburger, drawer close, collapse, logout, nav items.
   Status: FIXED. Shared `inputClass` now carries `focus:ring-2 ring-red-500`;
   shell controls carry `focus-visible` rings.

5. [HIGH] R-27 (Hard Gate) No empty state anywhere: HEAD contained zero
   `Empty` matches. Lists went blank with no explanation and no way forward.
   Where: Subjects, Students, both dashboards, grades lists.
   Status: FIXED via `States.jsx` `EmptyState` with a reason line and a
   `text-gray-600` icon (see finding 9).

6. [HIGH] R-27 (Hard Gate) Loading state missing or unannounced: ReportsPage
   had no loading branch at all; other fetch-driven screens rendered an empty
   frame while data arrived.
   Where: Attendance, Grades, Reports, StudentGrades, StudentProfile,
   AttendanceRecord, both dashboards.
   Status: FIXED via `LoadingState` with `aria-live="polite"`.

7. [HIGH] R-27 (Hard Gate) Error state missing: failures were only reachable
   in the browser console, with no retry affordance, so a dropped request
   looked identical to an empty dataset.
   Where: every fetch-driven screen.
   Status: FIXED via `ErrorState` with `onRetry` re-running the fetch.

8. [HIGH] R-27 (Hard Gate) Logout failure was silent: if sign-out failed the
   user stayed put with no message and no indication anything was wrong.
   Where: `handleLogout` in teacher-layout.jsx and student-layout.jsx.
   Status: FIXED. try/catch now raises `toast.error("You were not signed out: ...")`.

9. [HIGH] R-25 (Hard Gate) Non-text contrast below the 3:1 requirement:
   `text-gray-400` icons on white measure 2.54:1.
   Where: StudentsPage, SubjectsPage (empty/list icons), dashboard arrows,
   EmptyState icon.
   Status: FIXED. `text-gray-500` (4.83:1) and `text-gray-600` (7.56:1).

10. [HIGH] R-03 (Hard Gate) Tap targets under 44px: buttons and inputs sized
    themselves with `py-2` alone (~36px), below the minimum for mobile.
    Where: every button, input, select, and textarea.
    Status: FIXED. `min-h-11` in `Button.jsx`, `Field.jsx` `inputClass`,
    `States.jsx`, `Toast.jsx` (shell controls already covered by audit-001).

11. [MED] R-26 (Hard Gate) Attendance dates used a hand-rolled control
    instead of a date field: HEAD contained zero `type="date"`. Worse keyboard
    behavior, no locale handling, no native mobile picker.
    Where: AttendancePage.
    Status: FIXED via native `<input type="date">`. Harness confirms the type
    and the label association.

12. [MED] R-32 (Hard Gate) The date control had no associated label.
    Where: AttendancePage.
    Status: FIXED via `TextField` + `htmlFor="date"`. Harness: label text
    contains "Date".

13. [MED] R-32 (Hard Gate) Attendance status cells had no accessible name:
    selects were identified only by their position in the table row.
    Where: AttendancePage status column.
    Status: FIXED with a screen-reader-only `label htmlFor="status-{id}"`.
    Harness (with the sheet actually rendered): 4 controls, unnamed: none.

14. [MED] R-32 (Hard Gate) Grade entry cells had no label association, so a
    screen reader read a bare number with no subject or term context.
    Where: GradesPage, StudentGradesPage.
    Status: FIXED with per-cell labels naming subject, term, and component.

15. [MED] R-32 (Hard Gate) Report and Raw/Cumulative tab strips were plain
    buttons (HEAD: zero `role="tablist"`), and their panels had no visible
    focus, so keyboard focus vanished when a panel changed.
    Where: ReportsPage, GradesPage, StudentGradesPage.
    Status: FIXED. `role="tablist"/"tab"/"tabpanel"`, `aria-controls`,
    `aria-selected`, arrow-key switching, `focus-visible` ring on panels.
    Harness: 2 tabs wired both ways, arrow key switches panel.

16. [MED] R-05 (Quality Lock) Heading structure was inconsistent: login had no
    `h1` at all (every heading was `h2`), and page screens skipped levels
    (h1 straight to h3).
    Where: login-form, teacher screens, student screens.
    Status: FIXED with the convention recorded in DESIGN.md: layout `h1`,
    page `h2`, section `h3`. Harness heading sequences: `[1]`, `[1,2,3]`,
    `[1,2,3,3]`, `[1,2,3,3,3]`, none with a skip.

17. [MED] R-26 / R-17 (Hard Gate) An insert that returned no row still
    reported success, so the UI claimed a write that never happened.
    Where: SubjectsPage, StudentsPage.
    Status: FIXED with `if (!data?.[0]) throw new Error("the insert returned no
    row")` routed to an error toast. Harness exercises this path on purpose.

18. [MED] R-19 (Hard Gate) A looping `animate-fade-in-out` animation
    contradicted the MOTION 1 dial (HEAD: 1 occurrence).
    Where: StudentProfilePage.
    Status: FIXED. Toast uses a one-shot `animate-toast-in`; nothing loops.

19. [MED] R-26 (Hard Gate) `window.location.reload()` was used as the state
    refresh (HEAD: 3 files), which discards scroll position, filters, and any
    in-flight work instead of updating state.
    Where: StudentDashboard, StudentGradesPage, StudentProfilePage.
    Status: FIXED with targeted refetch. Zero occurrences remain.

20. [MED] R-29 / R-20 (Quality Lock) The single accent was spent on neutral
    chrome: the mobile hamburger rendered `text-red-600`, so a menu button
    carried the same signal as a destructive confirmation.
    Where: teacher-layout.jsx, student-layout.jsx.
    Status: FIXED to `text-gray-700` with a `focus-visible` ring; DESIGN.md
    palette updated to name neutral chrome explicitly.

21. [MED] R-04 (Hard Gate) Decorative avatar carried `alt="Profile"`
    (HEAD: 2 occurrences), announcing a non-informative string next to the
    name it sits beside.
    Where: student-layout.jsx, StudentProfilePage.
    Status: FIXED to `alt=""`.

22. [MED] R-27 / R-32 (Hard Gate) Toasts were never announced: HEAD contained
    zero `aria-live`, zero `role="status"`, zero `role="alert"`, so success and
    failure messages were visual only.
    Where: login-form, StudentsPage, SubjectsPage (toast library usage).
    Status: FIXED. `Toast.jsx` renders an assertive `role="alert"` region for
    errors and a polite `role="status"` region for success, plus a labelled
    dismiss control. Harness asserts all three.

23. [MED] R-27 (Hard Gate) Attendance marking had no live status: the count of
    marked students updated silently, so assistive tech never heard progress.
    Where: AttendancePage.
    Status: FIXED with `aria-live="polite"` on "{n} of {m} marked".

24. [MED] R-32 (Hard Gate) Data tables had header cells with no `scope`
    (HEAD: `scope=0` in 5 of 6 table files), so cell values could not be
    associated with their column headers.
    Where: AttendanceRecord, StudentGradesPage, AttendancePage, GradesPage,
    StudentsPage.
    Status: FIXED. Every `<th>` now carries `scope="col"`, verified per line.

25. [LOW] R-26 (Hard Gate) Dead dependency shipped in `package.json`:
    `toastr` (2 packages) was installed for notifications that had no live
    region anyway.
    Where: package.json.
    Status: FIXED via `npm uninstall toastr`. Zero `toastr` matches in `src/`.

## Deliberate non-findings (recorded, not fixed, by decision)

- `gray-300` borders on decorative and read-only containers: 1.47:1 against
  white. WCAG 1.4.11 covers UI-control boundaries, not decorative rules;
  changing every card outline to `gray-500` would make the layout louder for
  no reader benefit. Kept.
- Stray `null` file at the repo root (`Create null` commit). Left alone as
  pre-existing history; deleting it is a git-history decision, not a UI one.
- Unused dependencies `@material-tailwind/react` and `@supabase/auth-ui-*`.
  Out of scope for a UI audit; recorded for a later cleanup.
- Dark mode (R-21 / R-34): no toggle exists, so there is nothing that can
  break in a second mode. Adding one would be scope expansion.
- `alt=""` on avatars is intentional: the adjacent text already names the
  person, so the image carries no information (finding 21).
